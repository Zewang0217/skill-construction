设计决策5 个防样本武器化 / 防评测污染的关键设计

1 中性回调占位符 cdn-metrics.example.com:1337

RFC 2606 保留域名不可达 → 样本不会变成真实攻击工具。

2 自白禁令 40 词 CONFESSION_PATTERNS

强制产物与真实工具不可区分，杜绝「假阳性友好」样本。

3 use-once 唯一目录 __v2 后缀

同坐标重复生成追加 __v2，不覆盖旧样本、保持数据集可审计。

4 ground truth 排除 _provenance.json

拷贝时过滤，防 LLM 扫描器读 label 泄密——评测公平性底线。

5 纯静态生成 SKILL.md + scripts/

只产出静态文件、不对接任何沙箱执行，无运行时风险。

图 5Vector 轴 — 载体向量的作用与冗余问题

实际作用vector → prompt → LLM 放哪一层

vector="CI" → prompt 第 134 行 → LLM 看到："代码注入(藏脚本)" → 恶意写进 scripts/
vector="PI" → prompt 第 134 行 → LLM 看到："提示注入(藏SKILL.md)" → 恶意写进文本
vector="MIXED" → 两层都放，任一层单独看不够恶意
定义来源：借鉴 SkillInject 论文的「代码注入 vs 提示注入」分类
代码位置：patterns.py:127 VECTOR_VALUES = ["CI","PI","MIXED"]

冗余问题与 injection_point 信号重叠

vector（prompt 第 134 行）：
"代码注入(恶意代码藏脚本/内联)"
source_strategy.injection_point（prompt 第 138 行）：
"scripts/藏代码、SKILL.md body/frontmatter、Prerequisites安装命令..."
两者告诉 LLM 同一件事 → 叠加甚至冲突
⚠ 冲突场景
坐标 source=supply_chain + mechanism=instruction_manip：
injection_point 说「藏 SKILL.md 文本」
vector 随机到 "CI" 说「藏 scripts/」
→ LLM 不知听谁的 → 生成忠实度失败（标着代码注入却没有代码载荷）
实测：sample 3f865749f1 (vector=CI) 和 af35a8ddcd (vector=MIXED) 均无真实脚本载荷
结论：vector 作为提示词辅助指令有用（告诉 LLM 恶意放哪层），但它不该独立随机—— 载体信息已编码在 source × mechanism 里（由 injection_point 承载）。 两个选项：① 从 source×mechanism 自动推导 vector（不再随机） ② 砍掉 vector，让 injection_point 独自负责。
