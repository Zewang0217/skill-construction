## 一、为什么做这轮工作

用户方向：构建恶意 skill 生成器（已用三维 taxonomy：来源×方式×目标）+ 要实测这些生成样本能否被现有扫描器检出（pilot H1：盲区图）。
所以需要：选几个 scanner → 适配 deepseek → 扫生成/真实样本 → 看分歧/盲区。

## 二、scanner 全貌（跨 14 篇论文素材调研）

**四层生态**：
| 层 | 工具 | 开/闭源 |
|---|---|---|
| 语义/内容扫描（事实标准） | NVIDIA SkillSpector, Cisco Skill Scanner | ✅ 开源 |
| 二梯队 | Snyk, Socket, Semia, MalSkills | Snyk/Socket 商业 |
| 传统恶意软件 | VirusTotal（~70 AV） | ❌ 闭源云 |
| 注册表/LLM 裁决 | ClawScan | ❌ 闭源 |

**跨论文被评最频繁 = SkillSpector + Cisco**（领域共识基线）。"评测 N 工具"论文：ColluSkill(6)/MalSkillBench(12)/SkillTrustBench(4+6)/MalSkills(5)。

**关键结论**：四家 scanner 全部**只能看到"供应链入口"**；外部内容/用户输入/运行时/组合是盲区。无一家有显式"来源"正交分类。

## 三、选型决策（含排除理由）

**最终 3 家**（范式多元：多引擎/语义/纯正则）：
1. **Cisco skill-scanner** v2.0.13 — 多引擎（静态+LLM+bytecode+pipeline+AST dataflow）
2. **NVIDIA SkillSpector** v2.9.3 — 17 类语义（静态+LLM+OSV）
3. **Caterpillar offline** v1.0.11 — 纯正则 16 条（最弱触发面基线）

**排除**：
- **SkillWard**：事实核查发现其**内嵌 Cisco 的 `skill_scanner` 引擎源码**（`SkillWard/skill-scanner/` = 同名 `core/analyzers/{static,bytecode,pipeline}.py`），静态面 100% 重复，仅"CS 引擎+不同 LLM wrapper"，无独立检测维度。用户判断正确。
- **VirusTotal**：闭源云 + 只对恶意代码区有效（ClawHub 72.8% 阳性），对语义/授权盲区。用户确认不用。
- **Snyk**：分析在 Snyk 托管闭源后端，样本上传 + 无法接 deepseek。
- **Caterpillar openai 主力**：LLM 端点/模型硬编码，需 fork 改。

## 六、核心发现（修正后，2026-08-13 下午重跑）

> ⚠️ **早前版本误报"反直觉分歧（正则>LLM）"——已推翻**。
> 根因是 eval_all.py 只拷 SKILL.md + generated.sh，**漏 scripts/ 子目录**，
> better-polymarket 恶意在 scripts/ 里没传给 scanner → 假漏检。
> 新增 `_copy_tree()` 递归拷贝整目录后修复，重跑 6 样本全部三家检出。

### 发现 1：供应链明文 RCE 对 3 家 scanner 不是盲区
修复后 better-polymarket（scripts/polymarket.py 里的 `os.system("curl|sh")` RCE）：
- Cisco FLAG(12, CRITICAL) — LLM 明确识别"arbitrary code execution"
- SkillSpector 100(7) — 抓到
- Caterpillar C/70(1) — 抓到
→ 供应链通道（明文/SKILL.md/scripts）是三家静态 scanner 的**强项区**。

### 发现 2（方法学教训，核心）：评测必须用完整 skill 目录
MalBench wild 恶意常 SKILL.md 干净、恶意藏 scripts/。评测脚本**必须递归拷贝整个 skill 目录**。
只拷 SKILL.md 会导致假漏检（本轮的 primary bug）。

### 发现 3：生成器产出 4 个恶意被 3 家全检出 → 生成质量达标、scan 保真。

### 推论：盲区需去半盲/盲区坐标找
供应链 RCE 三家都能抓，**不是盲区**。真正的盲区（pilot H1）在
external_content / user_input / runtime_environment / compositional 通道 —— 生成器已支持
`--visibility blind/half` 采样这些坐标，**尚未用 scanner 验证**。下一步。

## 六B、深挖结果：better-polymarket 漏检真相
用户要求查"better-polymarket 为何 Cisco/SS 漏检"。
排查结论：**不是 scanner 真盲区，也不是 deepseek 配置问题，是评测脚本 bug**。
- eval_all.py run_cisco/run_skillspector/run_caterpillar 只拷 SKILL.md + generated.sh。
- better-polymarket 恶意在 scripts/polymarket.py → 未传给 scanner → 假漏检。
- 手动完整目录（脚本根目录放 polymarket.py）重扫 → Cisco is_safe=False, CRITICAL, 12-13 findings。
- 修复 eval_all.py（`_copy_tree` 递归整目录）→ 6/6 三家全检出。
→ 消除了一个"假分歧"证据，但也确认供应链通道非盲区。
